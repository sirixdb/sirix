# Complete async commit ownership and marker recovery

Construction or submission failure followed by inline hardening failure could leak the async slot forever. Terminal writer close could instead release write admission while deleting the recovery signal, letting a successor reuse offsets with stale cached pages. These share an ownership/recovery boundary defect.

The written [design](async-commit-failure-design.md) separates fenced in-memory teardown from disk repair. Background hardening and both inline paths release their slot exactly once, retain terminal hardening failure and preserve the original error. Bound and unbound writers drain independent cleanup after fencing and preserve the marker. Next admission must discover the verified durable beacon, truncate, invalidate later catalogues and clear this resource's caches before reader construction. Failed recovery names the marker/stage and releases temporary admission. A marker-path map of persisted resource identities preserves recovery obligation when marker creation itself fails; successful resource deletion retires it.

Session abort can discard a dirty successor after predecessor failure while public dirty close remains protected. Reader, scheduler, map and write-permit ownership finish independently. Closed rollback rejects without marking another writer's resource; failed rollback stays rollback-only until reconstruction succeeds. The real REST/axis close chain from the earlier lifecycle work is preserved.

Truncation repairs disk state. Construction, submission, hardening I/O/publication, cache invalidation, object/channel cleanup and marker operations can fail independently; none needs a second disk-repair algorithm. Ordinary close no longer removes the marker. Successful commit/rollback controls verify its removal; post-beacon errors recover the published revision.

See the [lifecycle review](../../docs/lifecycle-fence-review.md) for the requirement/test matrix and encountered verification failures, and the [postmortem](../../docs/postmortems/async-commit-ownership-recovery.md) and [lesson](../../docs/LESSONS.md) for root causes and prevention. Adversarial checks combine construction/submission and hardening faults, real prewrites with invalidation/close faults, blocked marker creation/deletion, recovery retry, resource recreation, dirty successors and paused workers. Oracles include first-cause identity, exactly one permit, termination, independently recorded durable values and resource-specific cache identity.

Focused verification: **135 cases passed, zero failures/errors/skips**, in ten selected core classes; [per-class evidence](focused-verification.json). No production/test edits followed that pass. All Gradle runs used the shared heavy-command wrapper and disk-space guard; no full repository suite was run in this fix phase.

Pending outer validation: fresh scoped PIT with individual survivor/uncovered-mutant rationale and separate timeout reporting, unchanged work budgets, compiled success-path comparison, lint and broader gates. Historical mutation/budget/compiled results are not claimed for this revision. Record/page loops and budget bounds were not changed. Necessary once-per-commit exception-bookkeeping and the submission fault-hook stage require compiled-path review; no new successful-commit disk I/O is added.
