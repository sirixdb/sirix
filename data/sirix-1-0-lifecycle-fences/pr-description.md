# Fence lifecycle workers and enforce callback ownership

Failed/interrupted parallel work could return while workers still used owner state; teardown could skip independent owners, and bounded REST iteration did not close nested prefetch producers. Async failure and callback reentrancy could also strand writer admission or permit unsafe offset reuse.

Worker fences now cover partial starts, interruption, reset and fallback. Iterator/stream/composite-axis closure reaches nested concurrent producers. Session/cache teardown preserves the first failure while attempting independent cleanup. Failed writers leave marker-driven truncation and resource-cache invalidation to the next exclusive admission; public dirty close remains protected. Node/page admission waits outside the session monitor and revalidates before construction.

Callback behavior is defined by [PreCommitHook](../../bundles/sirix-core/src/main/java/io/sirix/api/PreCommitHook.java), [PostCommitHook](../../bundles/sirix-core/src/main/java/io/sirix/api/PostCommitHook.java) and [revision listeners](../../bundles/sirix-core/src/main/java/io/sirix/access/trx/node/InternalResourceSession.java). The [ownership design](../../docs/ASYNC_COMMIT_DESIGN.md#failure-and-teardown-ownership) owns the shared notification, reader-retirement and truncation boundaries; the implementation-round notes below record their development.

## R12–R14: completion and late ownership

TXN-READ-1 closes every late direct/shared node reader after callback/worker fencing, before registry removal and page teardown; final admission revalidates against session closure. TXN-ASYNC-1 keeps each async notification batch owned by its epoch until hardening completion or final close, preserving successor overlap. TXN-ERROR-1 attempts independent callbacks, restores the phase, and rethrows retained Error from node close after owner release. RuntimeException-only logging and durable storage semantics are unchanged.

`sessionCloseClosesSharedReadersCreatedByFencedCallbacks` covers JSON/XML, real late navigation/guards and injected close failure while another reader still closes. `asyncHooksPreserveSuccessorOverlapAndCompletionOrder` proves the triggering setter and another successor mutation complete while hardening is latched, no callback runs early, and ordered notifications run on the completion dispatcher. `asyncCallbackErrorsRemainObservableAfterIndependentDeliveryAndClose` checks observed Error, later hooks, durable values and exact permit release. Hook order and pre-registration listener assertions now use recorded identities/awaited failure channels. The existing combined count+timer matrix still proves R11/review-1 clean rejection. See [postmortem](../../docs/postmortems/callback-completion-reader-ownership.md) and [current verification](callback-completion-verification.json); earlier counts remain historical. Fresh scoped PIT and compiled/work-budget evidence belong to the outer executor.

## R15: independent committed-revision views

TXN-VIEW-1 gives every post-hook its own read-only cursor at the exact published revision, opened/closed by dispatch and never sharing the mutable writer cursor. TXN-VIEW-2 preserves pre-hook timing, lifecycle rejection and async successor overlap; revision listeners carry only a revision number and must use independent readers. TXN-VIEW-3 removes borrowing-only lock acquisition overrides and keeps completion fencing solely for teardown and dispatch ordering.

`asyncPostHookNavigationCannotMoveTheCountOnlyWriterCursor` places the hook cursor on B while the count-only JSON writer updates A, then checks writer A=15/B=20 and hook committed A=13/B=20 at revision 3. `ordinaryPostCommitHooksContinueInOrder` checks per-hook fresh roots, exact revisions, genuine read-only types and closed cursors in JSON/XML. Existing combined count/timer rejection, async durability overlap, external close, late reader and Error matrices remain. Dispatcher views are not ordinary session-owned node registrations: the dispatcher closes them, and session teardown fences that job before page cleanup. A bounded JMH comparison uses the exact frozen a574857c lock and current simplified lock under the same harness; see current verification for measurements and limits. Historical 220-case results do not validate this revision.

The single authorized JMH comparison found no measurable regression after removing reservation acquisition checks: timed mutation 27.103 ± 0.971 → 26.993 ± 0.419 ns/op; nested commit/mutation locking 102.931 ± 8.256 → 101.001 ± 2.374 ns/op. Confidence intervals overlap, so no speedup is established. This measures uncontended lock overhead only; full I/O, contention, tail latency and database throughput are outside its scope. [Raw results](revision-view-lock-jmh.json) and the [harness](lock-benchmark/TimedTransactionLockBenchmark.java) are retained. Fresh mutation and broader compiled/work-budget gates remain pending with the outer executor.

## R16: writer fences before initial and late readers

TXN-TEARDOWN-1 separates ownership enumeration from close ordering: every node writer and its callbacks are processed before any ordinary node/shared reader, then the same ownership set refreshes late registrations. TXN-TEARDOWN-2 retains ordinary readers/pools when a node owner refuses teardown before fencing, while independent page-writer close attempts and all error accumulation still run. Maintenance reads remain available to already-started callbacks.

`sessionCloseFencesCallbacksBeforeInitialReaders` covers sixteen JSON/XML × direct/shared × interruption × cache/reader failure cases with an explicitly adverse identity snapshot and real navigation/guards before callback return. `refusingNodeOwnerRetainsOrdinaryReadersUntilRetry` checks retained real reader ownership and successful retry in both formats. Existing after-snapshot, pinned hook view, count-only overlap and mixed timer/count rejection matrices remain. See [postmortem](../../docs/postmortems/session-reader-fence-order.md) and [current verification](reader-fence-verification.json). The benchmarked lock implementation is unchanged; no new benchmark is run. Historical 229-case and JMH evidence does not validate this ordering correction; fresh focused results and outer PIT/compiled/work-budget gates are separate.

R16 final verification passed all 247 selected cases. Interruption tests also exposed a cached FileChannel reuse limitation after callback completion: immediate recovery can reject on a closed channel. ### Shared notification and history lifetime correction

Notifications now register shared resource completion ownership before node, immediate or maintenance dispatch. Session close delivers queued maintenance notifications while independent reads remain valid, then fences all shared callbacks before retiring direct/shared node readers, page readers and pools. Admission and final retirement serialize without waiting under a session monitor. Truncation fences local pinned views and rechecks hardening after callback waits release T; the shared page-writer truncation boundary excludes resource notification admission during destructive history changes. Normal TransactionExecutionLock lock/unlock, timed mutation callers and count-only row paths remain unchanged; no new benchmark was run.

The deterministic regression mapping is `SharedCallbackLifetimeTest` (cross-session JSON/XML, all three reader representations and publication modes, initial/late read admission, interruption, independent failure identity/suppression, admission-versus-retirement, and timed pinned distant-page reads versus truncate), the worker-arrival retirement regression in `TransactionExecutionLockTest`, and the updated permitted-read final-session oracle in `NodeTransactionAbortLifecycleTest`. The shared callback/history postmortem and LESSONS entry describe the ownership root cause and lock order. Fresh results are recorded separately; previous 247-case and benchmark results are historical, and scoped PIT plus final compiled/work-budget gates remain pending with the outer executor.

### Resource-wide reentrancy and pre-hook lifetime

The existing enclosing-execution rejection now consults cold registered writer ownership shared across user sessions before close snapshots or page-truncation waits. Public node truncation rejects enclosing execution at entry, retains its local callback/hardening fence and identifies its validated internal page operation through the existing execution context. A different resource remains independent. Pre-hook phases register completion through the existing shared callback boundary before entry and release it after context restoration, preserving synchronous veto timing and the exact thrown exception/error. Normal TransactionExecutionLock methods, runLocked, timed mutators and count-only row paths are unchanged, with no new benchmark.

`SharedCallbackLifetimeTest` maps the first invariant to same-resource sibling close/raw-page/public-node truncation rejection, no partial reader retirement, pending-hook/no-hook controls, different-resource operations and later normal closure. Its pre-hook matrix maps the second invariant to JSON/XML sync/async commits, initial/late direct/shared/page readers, success/RuntimeException/Error, interruption, independent first/suppressed cleanup errors and successful retry. The resource execution/pre-hook postmortem and LESSONS entry record the root causes. ### Idle page-publication delivery

The resource-wide reentrancy guard was already present at both selected wait callers and is retained. The remaining idle-dispatch gap is corrected at publication routing and page-maintenance boundaries: registered nodes receive notifications only under actual current-thread execution/scheduler ownership or explicit cold owner context. The async hardener supplies that context through hardening and superseded page close, then restores it before the unchanged slot-release/epoch dispatch. Raw truncation queues notifications while history/retirement ownership is held and delivers after release; raw close publishes after terminal payload cleanup. Operation failures retain priority over later callback failure. No normal lock/unlock, timed mutator, count-only path, benchmark, queue or thread was added.

`SharedCallbackLifetimeTest.rawPagePublicationDeliversBeforeSequentialSessionCleanup` covers JSON/XML, timed/untimed writers, raw truncate/bound close and success/listener Error. It asserts expected committed revision/value before the publishing call returns, released maintenance ownership, independent later listener delivery, Error identity, and sequential sibling/publisher session cleanup. The documented old-cursor lineage cleanup exception after destructive truncation remains distinguishable from an idle callback hang. Existing shared guard, pre-hook, pinned-view and overlap matrices remain in the focused selection.
