# Fence lifecycle workers and complete teardown

Interrupted or failed parallel work could return before workers stopped using owner state. Teardown could stop after the first failure, and early REST result abandonment did not propagate iterator close to concurrent producers. Async construction/submission and hardening failures could also strand ownership or erase the recovery signal before a successor reused offsets.

Projection directory walks, direct page scans and concurrent axes now fence started workers before fallback, reset or release, including interruption and partial start failure. REST serialization closes its result iterator on all exits; lazy sequences, streams and composed axes propagate closure to nested producers. Session and cache teardown attempt independent cleanup while preserving the first failure and suppressing later failures.

The [async ownership contract](../../docs/ASYNC_COMMIT_DESIGN.md#failure-and-teardown-ownership) and [marker recovery contract](../../docs/operations.md#marker-recovery) separate fenced teardown from disk repair. Session abort can discard a dirty successor after predecessor failure while public dirty close remains protected. Closed rollback rejects without marking another writer's resource; failed rollback stays rollback-only until reconstruction succeeds.

See the [lifecycle review](../../docs/lifecycle-fence-review.md) for the requirement/test matrix and encountered verification failures, and the [postmortem](../../docs/postmortems/async-commit-ownership-recovery.md) and [lesson](../../docs/LESSONS.md) for root causes and prevention. Adversarial checks combine construction/submission and hardening faults, real prewrites with invalidation/close faults, blocked marker creation/deletion, recovery retry, resource recreation, dirty successors and paused workers. Oracles include first-cause identity, exactly one permit, termination, independently recorded durable values and resource-specific cache identity.

Focused verification: **135 cases passed, zero failures/errors/skips**, in ten selected core classes; [per-class evidence](focused-verification.json). These results predate documentation and formatting housekeeping. The recorded test runs used the shared heavy-command wrapper and disk-space guard; no full repository suite was run in that fix phase.

Documentation/lint housekeeping reports its checks separately. Historical mutation/budget/compiled results are not claimed for this revision. Record/page loops and budget bounds were not changed. Necessary once-per-commit exception-bookkeeping and the submission fault-hook stage require compiled-path review; no new successful-commit disk I/O is added.

R6 follow-up: timed transaction and session-close hooks now complete teardown without joining their own scheduler. Later hooks stop at closed state; external transaction close still fences executor termination, including a repeated close after self-teardown. Cleanup waits hold no monitor needed by the scheduler hook, and admission release remains exactly once. See [the scheduler postmortem](../../docs/postmortems/scheduler-close-self-join.md) and the R6 mapping in the lifecycle review. Historical evidence predates this correction; fresh focused results and outer scoped mutation coverage are required.
