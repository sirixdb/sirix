# Async commit failure and recovery

Current contracts: [async ownership design](../../docs/ASYNC_COMMIT_DESIGN.md#failure-and-teardown-ownership) and the API references linked there. The round specifications below are historical, including superseded callback-close and execution-reservation proposals.

Decision: “A, but with a clear design of course. Why does the cleanup for instance fail? It should simply be a truncation once a \".commit\" file is in the resource”.

R4 is a shared completion-boundary defect. The implemented slot, failure and teardown contracts are owned by [the async commit design](../../docs/ASYNC_COMMIT_DESIGN.md#failure-and-teardown-ownership).

R5 is an ownership/recovery abstraction defect: closed means unusable, not recovered. After fencing workers, bound and unbound writers release independent in-memory ownership even when cleanup fails. Recovery is exclusively the existing marker-driven admission barrier. The same contract covers public clean close, explicit session abort, failed rollback and both node/page writer admissions, for XML and JSON. Public dirty close remains refused.

Truncation repairs persisted state. Successor construction, task submission, catalogue serialization, data/beacon writes, cache invalidation, listener/reader/log/backend close and marker I/O can independently fail; none warrants a second disk-repair algorithm. The admission contract and marker-creation failure handling are owned by [marker recovery](../../docs/operations.md#marker-recovery).

For the final teardown boundary, see [ResourceSession.close()](../../bundles/sirix-core/src/main/java/io/sirix/api/ResourceSession.java). Earlier proposed cleanup ordering and scheduler-initiated close below are superseded.

Successful hardening work and record/page loops retain their ordering. Recovery adds I/O only when the marker/guard is present. Failure-only marker retention and slot completion share boundaries; no retries or second disk recovery subsystem is added.

## Executable specification / independent oracles

- Construction or submission plus hardening failure: first injected error identity, suppressed hardening error, async permit count exactly one, repeated await retains cause; session abort frees the shared permit and scheduler in XML/JSON.
- Failed prewrite teardown: marker exists despite terminal writer state; a second user opens only after truncate/catalogue/cache recovery, sees the recorded durable value, commits a new value and reads it back. Bound/unbound owners obey the same barrier.
- Recovery fault at truncate/catalogue/cache stage: no reader construction or writer returned, marker-naming error and permit returned; clearing the fault permits recovery. Marker creation failure cannot produce a clean admission after the first session closes.
- Durable boundary: pre-beacon failure keeps revision 1; post-beacon cleanup failure keeps revision 2. An appended garbage tail is removed at admission, not teardown. Sibling resource caches remain usable.
- Existing real paused-worker tests cover R2/R3 and public dirty close; lifecycle iterator/axis tests remain unchanged.

This review phase runs one focused core verification round after all edits. Scoped PIT, work budgets, compiled-shape comparison and broader validation belong to the outer executor; no historical result is claimed for this revision.

Rollback ownership checks precede failure recovery: calling rollback on a closed node must reject without creating a marker or changing a successor writer's admission state. A failed rollback must reject mutations/commit until a successful rollback reconstructs the epoch. Existing rollback-only state provides that guard. The bound prewrite fault test uses the production KEEP_OPEN_ASYNC_FLUSH mode, whose epochs append to the reclaimable data tail rather than the default spill file.

## R6: scheduler-initiated teardown

A termination fence may only be performed by a thread outside the executor being fenced. Both XML and JSON timed transactions may close themselves, or their session, from a public post-commit hook. Such close completes node cleanup, publishes CLOSED, shuts down scheduling and releases admission exactly once without waiting for its own thread. Once a hook closes the transaction, neither synchronous nor asynchronous publication dispatches another hook. The timed callback then only returns through the lock-release/executor epilogue; it must never revisit readers, writers or epoch state.

Remember the scheduler worker's identity at thread creation, not by thread name. External close still waits for termination, including a repeated close after scheduler-initiated teardown. Do not hold the transaction monitor during that fence or while waiting for a timed transaction's lock: a scheduler hook can need to enter close concurrently. Timed cleanup uses its existing transaction lock; untimed cleanup remains serialized by its monitor. The existing admission-release guard becomes atomic so independent closers cannot release twice.

Regressions use real timed XML/JSON transactions, latches and a queued external closer. They prove transaction-close and session-close hooks return, another user reads the committed value and writes while the old hook is paused, no later hook runs on closed state, and external close returns only with the executor terminated. Bounded completion waits are deadlock guards, not performance assertions. Successful ordinary hooks retain their order; count-based asynchronous publication follows the same close-stops-hooks rule.

## R7/R8: complete teardown lock ordering

Confirmed: session close held the session monitor while waiting for a transaction lock, and public rollback held the transaction monitor while waiting for that lock. A timed callback already owns the transaction lock and can call either close entry point; those opposite edges create cycles. An open check made before acquiring that lock is stale once the callback closes the transaction.

Invariant R7: no session or transaction monitor may be retained while waiting for a timed transaction lock or scheduler termination. Invariant R8: rollback validates open state under the ownership lock, before maintenance and outside the failure catch that marks recovery. These hold for public rollback, transaction close, session rollback/abort, repeated/concurrent close, both formats and FILE_CHANNEL/IN_MEMORY.

Ordering: session inventory and close-attempt accounting use a short session-monitor section; transaction rollback/abort and scheduler fences run outside it. Timed node cleanup/rollback uses only the existing transaction lock. Untimed node cleanup/rollback remains serialized by the transaction monitor, with no timed scheduler to wait on. Internal abort owns rollback plus cleanup as one atomic node operation so competing session closers never issue a stale public rollback between node transitions. Scheduler self-close retains R6's safe epilogue; external node abort still fences after dropping its ownership lock/monitor.

After node owners have been processed, the session monitor serializes the existing independent-reader/cache/pool/storage/store cleanup and final state transition. An already completed concurrent session close skips that tail; any legitimate failure already retained is still reported. The short close-attempt count preserves the writer/user-session admission serialization formerly supplied by the whole-method monitor, including overlapping failed attempts; it is not a retry policy or disk-recovery mechanism. Node callbacks may register replacement readers during rollback, which the tail still collects. Unfinished workers retain dependent storage and remain retryable.

The hidden shared-session reference-count monitor is reached only by final registration release, after node shutdown/fencing; it never surrounds the user-session transaction phase. Store/database registration monitors likewise occur in that final phase. No transaction lock or scheduler wait may be moved into those monitor sections.

Executable matrix: timed XML/JSON callbacks calling transaction.close or session.close; external transaction.close, session.close or rollback queued behind the callback; FILE_CHANNEL and IN_MEMORY. Latches prove the external caller is queued before callback teardown. The callback must return, release admission once, skip later hooks, and leave no marker; file-backed checks read committed value 1, commit value 3 and read it back, while RAM checks empty-bootstrap admission plus mutation/rollback. Stale rollback must reject without poisoning marker recovery, which is independently demonstrated by successful IN_MEMORY write admission. An external session close in progress must reject a new writer on that same session while the callback remains paused.

RAM verification adjustment: the initial run passed 154/166 cases, including every file-backed interleaving; the 12 new RAM cases failed before entering the queued sequence because the fixture assumed persisted value revisions. RAM does not implement the file-backed revision/bootstrap protocol. Its root reference also used key -1 although the published root was stored under an allocated key, so the lifecycle root reader returned null. The additional invariant is that a published root's embedded page and storage key resolve the same object. Correct that reference at the RAM backend boundary; close, rollback and any keyed root consumer then agree without adding a second root-reading path. Keep unsupported truncation unchanged.

The RAM cases use an empty-bootstrap lifecycle oracle: timed publication of the empty resource, no marker or recovery guard, another user's actual mutation followed by successful rollback, and clean writer admission after the stale rollback finishes. File-backed cases retain the committed-value 1/3 durability checks. A direct RAM writer/read test publishes two different roots and checks that the returned reference reads the latest one by its key. This does not claim repair of unrelated RAM revision persistence or page-sharing behavior.

## R9: owner registration through admission release

Confirmed ownership flaw: the bound reader's close callback removed the node owner before scheduler fencing and write-permit release. A concurrent session close could then publish the session closed, causing the first closer's release callback to fail before its finally block; the node's atomic release guard had already been consumed.

Invariant: a registered node writer remains registered through reader cleanup and scheduler fencing until its shared write permit is actually released. This applies to ordinary public close, explicit session abort, both competing session closes, repeated close, final registry cleanup, and XML/JSON timed and untimed transactions. CLOSED describes unusable payloads, not completed admission ownership.

Ordering: reader callbacks retire only read-only registrations. After node cleanup and the existing external scheduler fence (or R6's safe self-close epilogue), the session monitor serializes node-owner removal and permit release as one short operation, with release in finally. The registry itself supplies exactly-once ownership; remove the separate pre-consumed atomic node guard. A later callback for an absent owner is a no-op, including after session closure. Session finalization preserves every internal node registration still present and cannot publish closed while any remains. No lock or executor wait occurs inside that release operation. Existing R7/R8 ordering and marker recovery remain unchanged; IN_MEMORY marker-policy changes are deferred.

Derived regression: pause the first closer at the real scheduler termination-check boundary after reader cleanup, with a second user holding resource lifetime. Assert the closed node remains registered and admission is held. Run another session close, which must discharge that same registered obligation before publishing closed. Resume the first closer and repeat close; admission must remain exactly one, maps empty, callbacks complete, and the second user must read the durable value, write and close. Cover XML/JSON, public transaction close versus session abort, timed/untimed schedulers, and a writer teardown failure. Existing timed hook tests retain the reentrant scheduler coverage; existing injected cleanup tests retain primary/suppressed-error checks.

Final registry cleanup retains internal node owners from the current registry, while preserving the previous retirement of ordinary read registrations and completed interface-only owners, including registrations created by cleanup callbacks. The initial node map copy is consequently unnecessary; the identity snapshot of transactions still drives cleanup outside the monitor.

## TXN admission ordering (R10)

TXN-ADMIT-1: Neither node-writer nor unbound page-writer admission waits for the resource write permit while retaining the session monitor. Validate parameters and current session state under a short monitor section, acquire admission without that monitor, then revalidate open/closing state under the monitor before constructing or registering any writer. Release the acquired permit in finally if revalidation or construction fails. The existing marker recovery barrier remains inside exclusive admission and precedes reader construction.

TXN-ADMIT-2: Owner removal and permit release remain atomic under the session monitor; node cleanup and scheduler fences never wait under that monitor. Thus admission uses permit acquisition followed by a short session-monitor section, while finalization only releases the permit and never waits for it under a monitor. Both node and page admission, ordinary node close, unbound page close, concurrent session close and construction failure obey this order.

Derived regression: queue each admission kind on an existing node or page owner, observe the semaphore queue, then close the old owner from another thread. Both calls must complete, admission must return a usable writer, and final close must restore exactly one permit. XML and JSON are covered; a session closing while admission is queued must make the eventual admitted attempt reject without constructing a writer or leaking admission. Callback dispatch contract clarification is pending because KEEP_OPEN holds this lifetime permit and PreCommitHook precedes publication; no change to either contract is inferred here.

## TXN callback contract (R11 / review-1, clarified)

This supersedes R6's accepted reentrant close behavior and the pending clarification recorded in R10. KEEP_OPEN retains lifetime admission P. Pre-commit hooks retain their before-publication/veto timing.

TXN-CB-1: One session-scoped callback context guards every pre-hook, post-hook and revision-listener dispatch, on every dispatching thread. Node/session lifecycle entry points reject that context with IllegalStateException before any lock, state change, recovery bookkeeping or scheduler wait. This also protects a captured node/session reference, not merely the hook argument.

TXN-CB-2: Post-hooks and revision notifications are queued at publication and delivered at the outermost execution boundary, after transaction lock T is actually released. A callback phase reserves payload ownership while T is free; competing execution waits for that phase to finish. Scheduled commits deliver only after their scheduled Runnable has returned, using the executor's completion boundary. Background hardening publishes notifications before releasing its async slot, and dispatches only after slot release; a foreground waiter drains those notifications before retiring payloads.

TXN-CB-3: An external close may never enter a scheduler termination wait with any enclosing T acquisition. Reject close/abort invoked from an arbitrary runLocked scope before cleanup, as well as rejecting callback lifecycle calls. Otherwise cleanup uses the existing execution boundary, then releases T before termination fencing and exactly-once admission release. No scheduler-thread close escape remains.

Lock order: admission waits for P outside the session monitor, then revalidates/registers under the monitor (R10). Transaction execution takes T and may use short session bookkeeping sections; session teardown snapshots under its monitor and drops it before acquiring T. Callback delivery drops T while reserving its execution phase; lifecycle attempts from that phase reject before acquiring either lock. Termination waits occur after T/phase release. Registry owner removal and P release remain one short session-monitor operation (R9). Marker recovery is unchanged.

Implementation boundary: a callback-aware execution lock supplies one outermost-unlock boundary for both JSON/XML mutators, nested runLocked, atomic scopes, foreground/count commits and scheduler completion. It queues work only when callbacks exist. Untimed transactions retain their no-lock row path; the same execution object serializes their cold lifecycle/callback boundaries. This necessarily changes the timed execution-lock implementation: no per-row allocation is introduced, but the added boundary checks require fresh outer compiled/work evidence rather than a historical unchanged-shape claim. Do not widen budgets.

Executable mapping: replace the superseded reentrant-close expectations with immediate rejection tests for pre/post/revision dispatch and commit/rollback/abort/node close/session close; cover foreground, mixed count+timer, scheduler and async hardening, XML/JSON. Assert T is not held during post/listener work, verify scheduler callbacks are outside the scheduled task, retain P until external teardown, and prove another user can write after external cleanup. Keep the late concurrent-close and queued-admission matrices. Include ordinary hook work/order, callback errors, nested runLocked, and arbitrary locked-close rejection as adversarial controls.

Post-publication errors are notification failures, not commit vetoes: deferred delivery cannot safely replace an exception already unwinding from a mutator or cleanup. The shared dispatcher therefore attempts each queued notification, retains the first error with later errors suppressed, logs it after restoring the execution phase, and leaves the durable transaction result intact. Revision observers already isolated RuntimeException; this rule also isolates Error and post-hooks. Pre-hook exceptions still propagate before publication and retain their veto semantics. This explicit adjustment is required by moving delivery outside the original execution boundary; it avoids a second exception channel or per-mutator exception plumbing.

Publication routing uses the current cold commit-execution context before registry lookup. A timer can start before node registration, and inline/background predecessor close can also publish while execution is nested. Foreground commits install/restore their owner context around publication, so listeners reach the same outermost boundary even before registration. Async hardening uses the registered owner, whose registration is retained through hardening-slot completion; a second worker-local owner context is unnecessary. Unbound/restoration publications retain registry/monitor routing. No publication event or revision value is deduplicated or changed.

TXN-CB-4: Every lineage-changing lifecycle operation fences a pending hardening slot before constructing a replacement writer or truncating storage. Commit, rollback/abort and close already await that slot; revert and truncate use the same wait before resource/revision validation and mutation. The fence prevents marker recovery or history truncation from overlapping the predecessor worker. Derive the same latch-controlled success/failure matrix for both commands, JSON/XML, retaining terminal cause and independently checked durable revision values.

## Callback completion and late reader ownership (R12–R14)

TXN-READ-1: After node workers/callbacks have fenced, teardown closes every currently registered shared/read-only node before clearing registrations or storage readers. Final read registration and shared-map insertion serialize with the session tail; an in-flight open that loses to final closure closes its newly constructed node. Maintenance reads remain available while callbacks are still running. This applies to JSON/XML, direct/shared admission, initial/late readers and independent close failures.

TXN-ASYNC-1: Notifications belonging to an async epoch are registered as a deferred batch owned by that epoch. Foreground outermost unlock and scheduler epilogues never drain these batches or wait for durability. Hardening completion releases its slot then dispatches that epoch's batch through the existing execution/callback boundary. Close, after awaiting hardening, may drain registered batches before retiring payloads. Each batch is removed once under T, so a prior dispatcher cannot consume a newer in-flight epoch's callbacks. Inline failure paths finish the same registered batch before unwinding; no additional executor or retry path is introduced.

TXN-ERROR-1: Dispatch attempts independent notifications and restores callback ownership. Node notifications retain the first Error (later failures suppressed) and rethrow it from final node close after owner release; this observed channel cannot replace an exception unwinding from a mutator. Unbound listener dispatch propagates Error after independent delivery; notification failures do not invalidate durable storage or bypass independent teardown. RuntimeException-only notification failures retain the existing logging policy. Hook/listener tests await an externally observed completion/failure and assert recorded identities outside dispatch, rather than relying on swallowed assertions or a call count.

Derived regressions: a blocked callback opens/navigates a shared reader after session close's snapshot; after release, both node/page closure and guard release must hold (JSON/XML). A held hardening barrier with two registered hooks must allow the triggering foreground setter and another successor mutation to return before release, deliver no notification early, then deliver hooks in registration order outside T/task ownership on the completion dispatcher. Existing count+timer/queued-scheduler rejection remains the R11/review-1 oracle. Callback Error regressions require later notifications attempted, external failure observation, durable data and exactly-once admission release. The pre-registration listener oracle records failures in an awaited future.

Focused validation exposed a callback-context representation mismatch: revision listeners belong to the shared resource and can run through another user session, including after their registering session closes. TXN-CB-1 therefore shares its ThreadLocal context with that same resource owner across user sessions; the active dispatcher and captured original session references agree. Existing combined-mode, pre-registration and final-session oracles exercise these sibling representations. No new lifecycle lock cycle was observed. A mocked terminal read-close fault must publish isClosed just as the real node reader does, while retaining its injected error and independent-owner assertions.

## Revision-pinned post hooks (R15)

TXN-VIEW-1 supersedes live-writer borrowing: every post-hook receives a fresh NodeReadOnlyTrx at exactly the published revision, opened and closed by the dispatcher, starting at the document root. It is never a NodeTrx and cannot mutate or share the successor's cursor. The revision is captured from the committed uber page for both synchronous and async paths, JSON/XML; each hook owns a distinct read view and cleanup attempts all hooks. Hooks may not retain the view. Pre-hooks retain their current timing and writer argument.

TXN-VIEW-2 retains R11/review-1 rejection before locking and R13 async overlap: async hooks are registered after successful hardening and dispatched after slot release and outer execution/task completion. Revision listeners carry only a revision number and must use independent readers rather than captured writer state. They share the lifecycle guard but receive no mutable cursor. Callback completion is fenced only by teardown; ordinary mutation lock acquisition never waits for callback completion. Count-only/no-lock row paths remain unchanged.

TXN-VIEW-3 removes the callback-borrow reservation from lock(), lockInterruptibly() and tryLock(). Outermost unlock detaches notifications under T and delivers them with T released; callback completion accounting retains session/reader lifetime for external close. Scheduled work still defers delivery until Runnable return. Close releases T while waiting for callbacks/task completion and never joins the scheduler under any enclosing T acquisition. Registered async batches remain drained once by their completion dispatcher or final closer.

Derived executable oracles: latch a post-hook with its independent cursor on JSON node B while the count-only successor changes intended node A; A must receive the new value, B remain unchanged, and the hook must still read the committed A/B values and exact revision. Cover per-hook fresh roots, read-only runtime type, closed views, JSON/XML explicit/count+timer/timer/async lifecycle rejection, external close, late reader cleanup and callback Errors. Update the former writer-borrow tests to independent revision views and job completion, with externally awaited failures. One bounded JMH comparison measures frozen a574857c versus simplified timed mutation/nested-commit locking on the same machine, through heavy.sh; report confidence and scope without claiming end-to-end commit latency.

## Writer fences precede all ordinary reader retirement (R16)

TXN-TEARDOWN-1: Session close processes every node writer, including its callback completion and scheduler fence, before closing any ordinary direct/shared node reader. The initial identity snapshot supplies ownership, never cleanup order. After writer processing, refresh the same reader ownership set and close all initial and late ordinary readers once. JSON/XML and direct/shared representations obey the same boundary; dispatcher-owned post-hook cursors keep their separate R15 lifetime.

TXN-TEARDOWN-2: If a node writer refuses teardown while still open, ordinary node/page readers and their pool remain dependencies of its callback source and stay owned for retry. Independent page-writer close attempts still run, preserving R2 completion and first-error/suppression. Do not clear registration or retire reader state merely because one close call failed or the closer was interrupted. Maintenance read admission remains available until all started callbacks are fenced. All actual waits remain outside the session monitor and release T as already designed.

Derived regressions: JSON/XML × direct/shared initial readers × closer interruption × injected cache/reader-close failures. Open/navigate the reader in a revision listener before session close; explicitly arrange and assert that the original identity snapshot visits a delegating reader before its real writer. Latch the callback, start close, observe its callback-completion wait, interrupt if selected, and navigate again before callback return. After release require node/page/guard cleanup, coherent registries, exactly one permit and original/suppressed failure identities. Keep the after-snapshot reader matrix. A refusing node-owner seam must retain real ordinary readers and allow retry to finish node ownership. No row loop or benchmarked TransactionExecutionLock change is permitted or needed.

## Resource notification admission and destructive history fences

TXN-NOTIFY-1: Every listener or post-hook notification admitted for a shared resource has a completion record shared by all user sessions, whether node-queued, immediate, or deferred by session maintenance. Reader retirement waits for those records outside session monitors and T. Admission and retirement serialize through a resource-shared read/write gate: admission uses a short read lease; retirement obtains the write lease only after completion and rechecks the admitted set. A new admitted notification cannot slip between quiescence and reader retirement.

TXN-NOTIFY-2: Monitor-held operations that can publish (node/page writer construction and the page-writer teardown stage) acquire their admission read lease before entering the session monitor. They enqueue tracked work and release the monitor before delivery. Close drains its maintenance notifications while the session is open, then obtains shared retirement ownership before ordinary node/page/pool cleanup. No callback wait retains a session monitor. This preserves permitted maintenance read admission and the shared pre-lock lifecycle guard.

TXN-HISTORY-1: truncateTo fences hardening and all local callback batches before invalidating storage. The cold execution fence rechecks worker completion after every release/reacquisition of T, so a successor hardening/batch admitted while it waited cannot be drained prematurely. Once locally quiescent under T, destructive truncation also obtains resource notification retirement ownership; remaining shared notifications use independent readers and require no T. Admission cannot race truncation. Neither ordinary mutation lock/unlock nor count-only row paths gain reservation checks.

Derived regressions: XML/JSON cross-user publication through a node writer, immediate standalone publication and queued final-session publication, with A's direct/shared/page readers opened before or during maintenance. A.close must wait for the shared completion; callbacks must open/navigate/close permitted readers and reject lifecycle calls before locks. Exercise interruption and independent cache/page close failures with original/suppressed errors and owner cleanup. A timed revision-2 post-hook pauses before distant-page navigation while truncateTo(1) waits; the view must remain readable until callback return, including interruption and hook Error. Prior pinned views, async overlap, R16 initial/late ordering and failure/retry remain required. No benchmark is authorized or required; only cold fence methods change in the benchmarked lock class.
