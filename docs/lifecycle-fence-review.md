# Lifecycle review fix handoff

R1: result closure must reach every owned producer before session teardown can close readers. The missing abstraction was close propagation across the axis composition tree and both descendant-expression iterator representations. Axis has a default close contract; composites forward it to every operand, and concurrent helpers close descendants on all exits. The JSON lazy iterator, cached descendant plans, JSON stream and XML stream forward closure. Cancellation preserves its primary failure and interruption.

R2: a live append worker's refusal must leave node cleanup retryable. Closing the node reader before the writer refusal had marked the transaction closed prematurely. The current session ownership contract is in [ResourceSession.close()](../bundles/sirix-core/src/main/java/io/sirix/api/ResourceSession.java); the async boundary is in [the design](ASYNC_COMMIT_DESIGN.md#failure-and-teardown-ownership). Real paused append workers cover both continued refusal and worker exit between the node and page close attempts, in XML and JSON.

R3: session abort must discard a dirty successor after a terminal predecessor-hardening failure. Public rollback cannot reconstruct that poisoned epoch, and public close must retain its dirty-transaction guard. InternalNodeTrx.abort shares the close ownership boundary while permitting explicit discard; it fences scheduler termination after releasing the node lock. Earlier errors remain primary and later cleanup errors are suppressed. The hardening worker now closes its detached predecessor and clears the pending revision root on failure. Failed-hardening commit markers remain present so the next writer performs the existing recovery before reading pages.

Regression oracles:
- Real compiled descendant queries, for item input and real document items wrapped in Brackit ItemSequence at the expression input boundary, stop after one serialized result; every real ConcurrentAxis executor terminates before serializer close, while readers remain live until session close and are then closed.
- Nested concurrent producers terminate on explicit close and reset; composite cleanup attempts both operands despite a failure; helper failure retains the original exception and suppresses descendant cleanup failure.
- Real node transactions in two user sessions retain the writer permit after writer refusal. NodeTransactionAbortLifecycleTest pauses an actual append worker, injects the already-expired timeout state without a timed assertion, and checks worker exit and retry. Both continued page-close refusal and worker exit before the subsequent page close are covered for XML and JSON. The second user reads the original committed value, commits a new value, and reads it back.
- NodeTransactionAbortLifecycleTest also runs a real KEEP_OPEN_ASYNC_COMMIT intermediate commit in each format, mutates its successor while hardening is paused, and fails hardening. Session teardown must wait for the worker, retain the original cause, close predecessor and successor writers, clear the pending root, terminate the scheduler, and admit another writer. Separate tests preserve the public dirty-close guard.

Steady-state iteration loops were left unchanged. New loops are confined to close-time ownership cleanup. No budget bounds changed.

## Unified R4/R5 ownership and recovery correction

Both findings are confirmed; they are shared-boundary defects rather than isolated bad lines. The [written design](../data/sirix-1-0-lifecycle-fences/async-commit-failure-design.md) was recorded before implementation. The [postmortem](postmortems/async-commit-ownership-recovery.md) answers why live-object cleanup can fail independently of disk truncation.

The final contracts are owned by [async failure and teardown ownership](ASYNC_COMMIT_DESIGN.md#failure-and-teardown-ownership) and [marker recovery](operations.md#marker-recovery). The pending-root registration/presentation failure interval is covered by the same inline completion boundary. Successful commit/record loops retain their existing work order.

Design adjustment: the recovery guard replaces retention of a terminal writer/permit. Normal admission adds a map lookup per transaction; no record/page loop was changed. The existing per-commit fault hook gains a submission stage; this is outside record/page loops and requires outer compiled-shape review. The stale-cache unbound regression now checks recovery on admission rather than cache invalidation during close, as required by the recorded design.

Spec/test map: inline double failures → `inlineDoubleFailureReleasesSlotAndRetainsPrimary`; bound/unbound cleanup failures → `terminalWriterFailureRequiresRecoveryWithoutStrandingAdmission`; marker failure → `failedMarkerCreationSurvivesSessionClose`; truncate/catalogue/cache failure and retry → `recoveryFailureRejectsAdmissionAndCanBeRetried`; post-beacon failure → `postBeaconCleanupFailureRecoversPublishedRevision`; reader cleanup → `readerGuardFailureStillReleasesNodeOwnership`. Existing paused append/hardening tests exercise R2/R3; existing writer construction, commit safety, recovery ordering and async flush tests cover ordinary successful callers. The unbound prewrite test checks actual cache removal and sibling preservation.

Fresh mutation, work budgets and compiled-shape evidence remain required from their outer phases. Historical counts above do not validate this correction. No full suite, pipeline control, publication or integration is performed in this review fix phase.

## R6: scheduler-initiated close

Confirmed ownership defect: timed post-commit hooks execute inside their commit scheduler. Public transaction close and the session-close/abort route both reached an unconditional wait for that same executor. The invariant is shared by XML/JSON, both close entry points, both post-commit dispatch loops and repeated external close.

The scheduler worker is identified by its actual thread reference at creation. Self-close drains the existing ownership boundary, shuts down future scheduling and releases admission without self-joining. Both hook loops stop immediately when a hook closes the transaction. After the closing hook returns, the timed task only returns `self()` and unlocks; neither operation accesses retired reader/writer payloads. Session-close rollback/abort and reader/storage teardown complete before that hook returns. External transaction close always fences scheduler termination, even when an earlier self-close already released the permit. It waits outside the transaction monitor. Timed in-memory cleanup uses the existing transaction lock and untimed cleanup keeps monitor serialization; the existing exactly-once release guard is atomic to cover independent closers.

Regression mapping: `timedPostCommitCloseReleasesAdmissionWithoutJoiningItself` covers transaction-close and session-close hooks for both formats, a queued external closer, admission and durable values while the callback remains paused, suppressed later hooks, eventual executor termination and exactly one release. `ordinaryPostCommitHooksContinueInOrder` preserves normal hook behavior. `asynchronousPostCommitCloseStopsLaterHooks` applies the same callback-stop rule to count-based publication. The [postmortem](postmortems/scheduler-close-self-join.md) records the causal chain and prior coverage gap.

This correction changes transaction setup, hook dispatch and close only; record/page loops and budget bounds remain unchanged. Earlier mutation/compiled-shape results and passing counts above do not validate R6. Fresh scoped PIT and broader validation remain with the outer executor; this fix round runs focused core lifecycle/caller tests only.
