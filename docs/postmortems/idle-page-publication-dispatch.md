# Bug: idle page publications had no delivery boundary

- Fix / issue: review-idle-publication-dispatch; retained review-shared-retirement-reentrancy.
- Symptom: a raw page truncate or bound page close admitted a listener completion onto an idle registered node writer. Sequential sibling-session cleanup waited for that completion before it could reach the publishing writer's next lifecycle operation.
- Trigger: JSON/XML user sessions A/B, B's untimed writer commits revisions 1/2, then a raw page truncateTo(1) outside runLocked publishes to a listener. A.close waits before B.close can drain the notification. A bound raw page close has the same delivery gap.
- Root cause: registration was used as a proxy for active execution. Page maintenance published before its own cleanup/retirement boundary but had no outside-lock delivery step.
- Why tests missed it: standalone publications had no registered node owner; bound maintenance was tested under node execution or rejected nested truncation. The earlier shared guard regression was already implemented and remains unchanged.
- Regression test: SharedCallbackLifetimeTest.rawPagePublicationDeliversBeforeSequentialSessionCleanup covers JSON/XML, timed/untimed writers, raw truncate/bound close and listener success/Error. It requires listener navigation of the expected revision/value before the page operation returns, no execution/session/retirement locks during notification, independent subsequent listener delivery, original Error identity and sequential A/B cleanup without a callback hang. Existing shared reentrancy, async overlap and node/unbound maintenance cases are retained. Pre-fix execution was not run in this round; final focused results are recorded separately.
- Lesson: a registered owner is not a completion boundary; route only to active ownership and deliver idle notifications at the operation that admitted them. See [the lesson](../LESSONS.md).

Cold publication routing now checks explicit owner context or current-thread execution/scheduler ownership. The async worker installs the existing owner context during hardening and superseded page close, restores it before releasing the slot, then retains the existing epoch dispatch. Idle truncation queues while retirement is held and drains after history/retirement release; monitor maintenance retains its existing outside-monitor drain. Page close publishes after terminal payload retirement. First maintenance failure remains primary, with later listener failure suppressed. No new state, queue, thread or mutation-path bookkeeping is introduced.

Focused outcome: 386 selected tests passed (378 core/eight query), zero failures/errors/skips. Configured auxiliary tasks ran 45 cases with two skips and no failures. The final lifetime class has 138 cases. `data/sirix-1-0-lifecycle-fences/idle-publication-verification.json` binds scope, exact classes, final source hashes and limitations. Raw destructive truncation can still produce its documented old-lineage IllegalArgumentException during subsequent session abort after owner release; the regression accepts only that exact truncation cleanup exception and still requires terminal ownership/permit release. Scoped PIT and final compiled/work-budget checks remain with the outer executor.
