# Bug: comment cleanup expanded the correctness mutation workload

- Fix / issue: PR #1352; [failed PIT run](https://github.com/sirixdb/sirix/actions/runs/43932263466/job/133530308551).
- Symptom: query mutation analysis timed out with a 790-second remaining share; no complete query verdict was produced.
- Trigger: the documentation commit changed comments in five previously unchanged core sources and `ScaleBenchMain`.
- Root cause: changed-source PIT intentionally selects whole source files. The comments added a core analysis (10 classes, 16 test patterns) and benchmark package discovery, expanding query selection from 21 to 44 patterns. Core consumed approximately 530 seconds of the shared 1,320-second budget.
- Invariant (before repair): comment-only cleanup must not expand this correctness change's mutation workload. This applies to both configuration comments in `ResourceConfiguration`, the `PathNode` field comment, `PathStats` class documentation, `PathSummaryReader.findPathsByLocalName`, `PathSummaryWriter.invalidateStatsForMovedSubtree`, and the `ScaleBenchMain` statistics setup comment.
- Fix: remove only those six Java comment patches from the documentation commit. Retain the updated public Markdown contracts and all functional fixes. Keep selector semantics, mutation thresholds, sampling, test assertions and deadlines unchanged.
- Why earlier checks missed it: documentation review did not inspect the executable selector's final module/test inventory; a comment-only edit still selects all mutants of its source.
- Regression / acceptance checks (specified before repair): execute the existing selector against the resulting worktree diff and compare its emitted module/target/test inventory with the functional parent. The independent oracle is that parent's nine query sources, 71 compiled target classes and 21 test patterns, including the release correctness suite. The hosted artifact supplies the failing expanded inventory. Run the existing Python selector/reporting tests and the complete bounded PIT consumer on the restored inventory; incomplete analysis remains a failure. No source-text assertion is added as a substitute for behavior.
- Path audit before verification: removal changes no executable Java statement, caller, branch, field, signature or state transition. Statistics writers/readers, resource configuration and benchmark startup retain the functional parent's implementation; query admission/refusal, count-wrapped grouping, both pipeline strategies and warm/reopened execution remain in scope.
- Lesson: inspect the final mutation selection after documentation edits; defer incidental Java comment cleanup when it adds unrelated whole-source analysis to a bounded correctness gate. See [Lessons](../LESSONS.md).
