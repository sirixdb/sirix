# Bug: callback completion lost async overlap and late reader ownership

- Fix / issue: V05/V06 R12–R14; R11/review-1 checked against 74385a1f.
- Symptom: a registered no-op hook made async commits wait for durability on the foreground mutator; session close discarded callback-created node readers while retaining their guards; swallowed assertion Errors made ordering checks ineffective.
- Trigger: hold the depth-one hardening barrier with post-hooks registered; or block a callback, start session close, then open/navigate shared and direct readers before returning. Reversed hook order or rejected lifecycle assertions could be logged without failing the former counter-only oracle.
- Root cause: all callbacks shared the foreground-drained queue and waited for the async slot, teardown refreshed page owners without refreshing node owners, and tests confused callback attempts with validated order. The same failure boundary caught Error without an externally observed channel.
- Why tests missed it: the settled 210-case run never started; the diagnostic 198-case pass predates final edits. The previous async borrow test used listeners but no post-hooks; teardown assertions observed initial owners; hook-order assertions lived inside a swallowing dispatcher.
- Regression test: `asyncHooksPreserveSuccessorOverlapAndCompletionOrder` holds real hardening, requires foreground and successor progress before release, records exact ordered identities on the completion dispatcher, and checks durable value 2. `sessionCloseClosesSharedReadersCreatedByFencedCallbacks` opens real JSON/XML shared/direct readers after the close snapshot and checks node/page closure and guard release with/without injected close failure. `asyncCallbackErrorsRemainObservableAfterIndependentDeliveryAndClose` requires the original Error after later notifications, closed owners, one permit and durable value 1. `ordinaryPostCommitHooksContinueInOrder` asserts recorded identities externally; the pre-registration listener oracle awaits its failure channel. `TransactionExecutionLockTest` checks independent Error delivery and separate epoch/final-close ownership. The existing mixed count+timer scheduler-queue test remains the R11/review-1 rejection oracle. No pre-fix executable run is claimed.
- Lesson: attach notifications to hardening completion instead of waiting in foreground dispatch; refresh both node and page ownership after callbacks fence; observe callback validation outside the dispatcher. See [Lessons](../LESSONS.md).

The governing [TXN requirements](../../data/sirix-1-0-lifecycle-fences/async-commit-failure-design.md#callback-completion-and-late-reader-ownership-r12r14) preceded these fixes. Async batches use the existing worker and execution boundary, with no extra executor, retry or per-row allocation. A completed batch is drained exactly once by its completion dispatcher or the final closer. Foreground unlock never consumes deferred epochs. Node closure still joins the scheduler outside T, releases admission through the unchanged registry boundary and preserves the marker recovery policy.

Node Error delivery is now observable through final close after independent notifications, phase restoration and permit release. Recording at the node boundary prevents a notification Error from replacing an exception unwinding from an enclosing mutator; unbound listener dispatch propagates after independent listeners. RuntimeException-only logging remains. Notification Error does not itself require storage recovery. Original execution/cleanup failures remain primary, with later failures suppressed. Final read registration serializes with session finalization; maintenance reads needed by callbacks remain permitted until those callbacks finish.
