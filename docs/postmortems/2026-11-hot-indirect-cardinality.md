# Bug: HOT indirect cardinality contracts disagreed

- Fix / issue: captain call 6 (H10).
- Symptom: MultiNode factories accepted one child although I10 and the validator require at least two; persisted corrupt counts reached layout decoding and allocation before validation.
- Trigger: create a single-child MultiNode in either mask layout, or decode an indirect header with child count 1.
- Root cause: the lower bound was implemented independently by factories, node-type selection, structural detection and writer guards, with inconsistent domains. The persisted count had no early validation.
- Why tests missed it: factory tests exercised ordinary fanouts; traversal-budget fixtures even used unary nodes as convenient malformed shapes, implicitly relying on the permissive factory.
- CI follow-up contract: type selection and upgrade checks reject counts outside 2–32. Deletion checks return true for 0 children (remove) and 1 child (collapse), for either node type; legal counts retain the SpanNode/MultiNode threshold at 16/17. The stricter selector exposed four legacy suites that still classified one child as a SpanNode, and `shouldDowngrade` delegated the unary deletion state to that selector. The regression tests execute these interfaces against I10 and the deletion contract, rejecting either accidental unary acceptance or a thrown exception instead of collapse.
- Regression test: `HOTIndirectCardinalityTest` executes every factory and COW form, round-trips legal minimum fanouts, supplies truncated corrupt headers for both layouts and node types, and injects malformed in-memory cardinalities into detection and writer preflight. `NodeUpgradeManagerTest` rejects one child. Budget fixtures use binary chains so they still exercise page limits and cycles.
- CI follow-up evidence: `./gradlew :sirix-core:test --tests '*NodeUpgradeManagerTest*deletionTransitionsRespectMinimumFanout*' -PtestHeapMin=512m -PtestHeapMax=2g` failed before the repair for both node types. After repair and rebase, 84 focused tests passed (the four legacy node-type suites, `NodeUpgradeManagerTest`, `HOTIndirectCardinalityTest` and `HOTRebuildFootprintTest`), as did Spotless and the repository Checkstyle rules. A full-class PIT run with `NodeUpgradeManagerTest*` killed all six `shouldDowngrade` mutants and all eight `determineNodeType` mutants. The three survivors at unchanged `isUnderfilled:336` (conditional boundary, multiplication-to-division, constant-true return) are outside this fanout repair; its focused tests only exercise underfilled nodes. Uncovered mutants in unchanged `mergeToSpanNode` (14), `upgradeToMultiNode` (9), `downgradeToNode` (8) and `shouldMergeToSpanNode` (1) likewise belong to other operations, not the repaired deletion decision.
- Lesson: enforce the same structural domain at construction, decoding and publication boundaries; see [Lessons](../LESSONS.md).
