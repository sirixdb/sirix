# Bug: lifecycle CI depended on storage interruption details

- Fix / issue: PR #1353; CI run 43717210995.
- Symptom: macOS rejected a valid cancellation outcome; Sonar rejected a throw in finally and lifecycle-specific patterns; PIT exhausted its shared deadline.
- Trigger: interrupt a parallel projection walk while worker readers are held; independently fail hardening and pending-root retirement.
- Invariants: cancellation fences every started worker and releases every reader before return; cleanup preserves the first failure; successful hardening remains published even when retirement fails.
- Scope: all four projection failure modes, background and both inline hardening callers, JSON/XML node ownership, session/reader/writer/cache/composite-axis cleanup. Broad unchecked catches must retain Error as well as RuntimeException and must not be narrowed to satisfy analysis.
- Root cause: the lifecycle test mixed a worker-fence assertion with operating-system-dependent FileChannel cancellation. The hardening method threw from a nested finally despite already maintaining a failure accumulator. Sonar also mistakes volatile publication for synchronization of the helper's contents, although all consumer accesses are synchronized and producer state is read after executor termination.
- Why tests missed it: local file I/O produced ClosedByInterruptException; macOS exposed an unresolved HOT route instead. The pending-root test covered double failure but lacked the successful-hardening/failed-retirement case.
- Regression test: ProjectionParallelDirectoryWalkTest delegates to real file-backed readers and injects one known cancellation exception at the coordinating reader boundary only after interruption, requiring that exact failure, no partial result, restored interrupt status and zero active readers. The other three failure modes and serial/parallel differential tests retain real storage. NodeTransactionAbortLifecycleTest.pendingRootCleanupRetainsFirstFailure covers both formats with and without hardening failure, checking exception identity, suppressed failures, worker cleanup and the durable value.
- Analysis exceptions: method-scoped java:S1181 permits required best-effort cleanup after Error; java:S3077 on the test hook covers publication of a caller-supplied thread-safe callback. The helper reference needs no volatile because its accesses are synchronized. Legitimate complexity findings remain visible; removing required-cleanup false positives addresses the debt gate (1160 of the reported 1459 remediation minutes concern S1181). No project-wide rule is disabled.
- Original CI PIT evidence: the artifact has no mutation XML. Full-module coverage discovery included ValidTimeDisabledLookupCacheTest and GlobalValueDictionaryReadViewMissPathTest in a shared minion even though they require dedicated JVMs, and exhausted 1320 seconds before mutation. This is incomplete analysis, never a clean score; this fix does not widen its budget or silently reduce its targets.
- Lesson: [test ownership independently of storage cancellation](../LESSONS.md).
