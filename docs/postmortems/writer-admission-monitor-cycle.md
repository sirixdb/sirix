# Bug: writer admission blocked the closer that releases admission

- Fix / issue: lifecycle audit V05/V06, review R10. The broader callback redesign for R7/R9/R11 awaits clarification of KEEP_OPEN permit ownership and pre-commit timing.
- Symptom: a new writer on a session timed out after five seconds (node admission) or twenty seconds (page admission), while the existing owner could not finish close.
- Trigger: queue node or page admission behind an existing owner, then close the owner or its resource session from another thread.
- Root cause: synchronized admission retained the session monitor during semaphore acquisition, while node reader deregistration and write-owner release required that monitor. This violated the shared rule that a closer must be able to discharge admission while admission is queued.
- Why tests missed it: prior matrices raced closers with one another or callbacks; none queued a same-session writer behind the old writer before closing it. A second user session has a distinct monitor and does not reproduce this cycle.
- Regression test: `NodeTransactionAbortLifecycleTest.queuedWriterAdmissionDoesNotHoldTheSessionMonitor` covers 16 format/owner/admission/close combinations. Semaphore queue observation establishes the interleaving. Bounded futures require completion, new node writers read durable value 0 and commit value 3, page writers return usable, and final permit counts equal one. If session close wins, admission rejects with IllegalStateException before construction, and another user still opens and reads the durable revision. The old code cannot complete the closer while admission retains its monitor; its forced admission timeout fails the regression. No pre-fix run is claimed.
- Lesson: enumerate all permit acquisitions and releases in the lock graph, including setup and bookkeeping callbacks; see [Lessons](../LESSONS.md).

The governing [TXN admission specification](../../data/sirix-1-0-lifecycle-fences/async-commit-failure-design.md#txn-admission-ordering-r10) precedes tests and implementation. Both admission paths now validate under a short monitor section, wait outside it, and revalidate under it before allocating or registering readers/writers. Failure releases the acquired permit in finally. Marker-driven recovery and existing owner-registration/fencing semantics remain unchanged. No row/page-loop changes are included. Fresh mutation and compiled-path evidence remain with the outer executor.
